## STUDY1_260810

이 블로그를 만들면서 가장 크게 얻은 건 완성된 사이트가 아니라, **셋이 각각 무슨 일을 하는지**가 손에 잡혔다는 점입니다. 예제를 따라 칠 때는 그냥 "웹 만들려면 세 개 다 필요하다" 정도였는데, 직접 한 줄씩 붙여보니 역할이 확실히 갈렸습니다.

한 문장으로 줄이면 이렇습니다.

> HTML은 **무엇인지**, CSS는 **어떻게 보일지**, JavaScript는 **무슨 일이 일어날지**를 담당한다.

### HTML — 구조와 의미

HTML은 화면을 예쁘게 만드는 게 아니라, 이 덩어리가 **무엇인지** 선언하는 언어였습니다.

같은 글자라도 `<div>`에 담으면 그냥 상자지만, `<article>`에 담으면 "독립적인 하나의 글"이라는 뜻이 됩니다. 이게 왜 중요하냐면, 그 의미를 읽는 쪽이 사람만이 아니기 때문입니다.

- 스크린 리더는 `<nav>`, `<main>` 같은 태그를 보고 "본문으로 건너뛰기"를 제공합니다
- 검색 엔진은 `<h1>`과 `<p>`의 차이로 무엇이 제목인지 판단합니다
- 브라우저는 `<button>`이면 키보드 Tab과 Enter를 알아서 처리해 줍니다

마지막 항목이 특히 인상적이었습니다. `<div>`로 버튼 모양을 만들면 눈에는 버튼처럼 보이지만 키보드로는 아예 누를 수가 없습니다. 그걸 되살리려면 JavaScript로 직접 구현해야 하는데, 처음부터 `<button>`을 썼다면 공짜로 얻는 기능입니다.

날짜도 마찬가지였습니다.

```html
<time datetime="2026-08-10">2026년 8월 10일</time>
```

사람은 "2026년 8월 10일"을 읽고, 기계는 `datetime` 속성을 읽습니다. 하나의 태그가 두 독자를 동시에 상대합니다.

### CSS — 표현

CSS는 HTML을 건드리지 않고 겉모습만 바꾸는 층입니다. 이 분리가 실제로 얼마나 강력한지는 **다크 모드**를 만들면서 체감했습니다.

색을 규칙마다 직접 적지 않고, 변수로 한 번만 정의해 두면:

```css
:root {
  --bg: #fbfbfa;
  --text: #1f2328;
}

@media (prefers-color-scheme: dark) {
  :root {
    --bg: #16181c;
    --text: #e2e4e8;
  }
}
```

HTML은 한 글자도 안 바뀌었는데 사이트 전체 색이 뒤집힙니다. 변수 몇 줄이 전부입니다.

반응형도 같은 원리였습니다. 모바일과 데스크톱용 HTML을 따로 만드는 게 아니라, 하나의 HTML에 화면 폭에 따라 다른 CSS를 얹습니다.

| 화면 폭 | 본문 크기 | 본문 폭 |
| --- | --- | ---: |
| 767px 이하 | 17px | 화면에 꽉 참 |
| 768px 이상 | 18px | 740px 고정 |

여기서 배운 규칙 하나. **모바일을 기본값으로 쓰고 넓은 화면을 얹는 편이 쉽습니다.** 반대로 하면 좁은 화면에서 계속 무언가를 되돌리는 코드를 쓰게 됩니다.

또 하나 의외였던 것: 본문 폭을 일부러 좁게 **제한**한다는 점입니다. 화면이 넓다고 글을 끝까지 채우면 한 줄이 너무 길어져서, 눈이 다음 줄 첫머리를 찾기 어려워집니다.

### JavaScript — 동작

가장 놀란 부분입니다. 이 블로그에서 브라우저로 내려가는 JavaScript는 **테마 토글 버튼 하나뿐**입니다.

글을 읽고, 링크를 누르고, 다크 모드로 보고, 모바일에서 보는 것까지 전부 HTML과 CSS만으로 됩니다. JavaScript가 필요한 건 "사용자가 버튼을 눌렀을 때"처럼 **시간이 흐르며 무언가 변하는** 순간뿐이었습니다.

```javascript
button.addEventListener('click', function () {
  // 눌렀을 때 테마를 바꾸고 저장한다
});
```

그리고 여기서 헷갈렸던 걸 하나 정리하게 됐습니다. 이 프로젝트에서 JavaScript는 **완전히 다른 두 자리**에 등장합니다.

1. **빌드할 때** — 마크다운 파일을 읽어서 HTML로 바꾸는 프로그램. 내 컴퓨터에서 돌고, 방문자에게는 전달되지 않습니다.
2. **브라우저에서** — 방문자가 페이지를 열었을 때 같이 내려가서 실행되는 코드.

같은 언어지만 도는 장소도 목적도 다릅니다. 1번이 아무리 커져도 사이트 속도와는 무관하고, 2번은 한 줄 늘 때마다 방문자가 받아야 할 짐이 늘어납니다.

### 정리하며

| | 담당 | 없으면 |
| --- | --- | --- |
| HTML | 무엇인지 | 내용 자체가 없음 |
| CSS | 어떻게 보일지 | 못생겼지만 읽을 수는 있음 |
| JavaScript | 무슨 일이 일어날지 | 대부분 그대로 동작함 |

세 번째 칸이 핵심이었습니다. JavaScript를 빼도 이 블로그는 여전히 읽힙니다. 그래서 "일단 JavaScript로 해결"하기 전에 **HTML이나 CSS로 안 되는지 먼저 묻는 습관**이 남았습니다.
